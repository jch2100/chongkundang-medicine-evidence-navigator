# DATA DICTIONARY v0.2

이 문서는 데이터 생성(백엔드)과 화면(프론트엔드)의 **계약**이다. 양쪽 모두 이 문서를 기준으로 작업하고, 필드를 바꾸려면 이 문서를 먼저 고친다.

---

## 0. 절대 원칙

**허가 ≠ 급여 ≠ 청구.** 세 가지는 근거 문서가 다르므로 한 필드에 합치지 않는다.

| 층 | 근거 | 파일 |
|---|---|---|
| 허가 | 식약처 품목허가 (품목기준코드) | `items.json` |
| 급여 | 약제급여목록 및 급여 상한금액표 (고시) | `billing.json` |
| 청구 | 의료진 판단 — **이 도구가 제공하지 않음** | — |

화면은 보험코드·상한금액 옆에 항상 **기준일**과 **출처 고시명**을 함께 표시한다.

---

## 1. 계층 구조

```text
브랜드(brandId)        영업·검색 단위       예: dilatrend
 └ 품목(itemKey)       허가 단위            예: 딜라트렌정6.25mg / 품목기준코드 199800085
    ├ 포장(kdCode)     유통 단위(표준코드)   예: 10정 PTP → 8806433003715
    └ 청구(ediCode)    보험 청구 단위        예: 643300370
```

**품목 키는 `품목기준코드` 단독이 아니라 `품목기준코드 + 업체명`이다.** 공동판매 품목은 허가(품목기준코드)를 공유하고 표준코드만 업체별로 다르다.

> 실증: 자누비아 `200710759` → 종근당 `8806433095505`(보험코드 643309550) / 한국엠에스디 `8806555003204`(보험코드 없음)

## 2. `data/public/items.json`

```jsonc
{
  "schemaVersion": "0.2.0",
  "generatedOn": "2026-09-22",
  "source": {
    "standardCode": "건강보험심사평가원_약가마스터_의약품표준코드_20260831.csv",
    "ingredient": "건강보험심사평가원_약가마스터_의약품주성분_20251031.csv"
  },
  "items": [
    {
      "itemKey": "199800085::(주)종근당",   // 품목기준코드::업체명 — 고유키
      "itemSeq": "199800085",              // 품목기준코드 = 식약처 itemSeq
      "brandId": "dilatrend",              // products.json 의 id. 대응 id 가 없으면 null
      "brandNameRaw": "딜라트렌",            // 매칭된 브랜드 문자열. brandId 가 null 일 때 필수
      "itemName": "딜라트렌정6.25mg(카르베딜롤)",  // 허가명 그대로. 가공 금지
      "company": "(주)종근당",
      "isCkd": true,                       // company 에 '종근당' 포함 여부
      "strengthLabel": "6.25밀리그램",       // 약가마스터 '약품규격' 원문
      "rxClass": "전문의약품",
      "approvalDate": "1998-04-09",
      "cancelDate": null,                  // 값이 있으면 취소 품목
      "atcCode": "C07AG02",
      "ingredientCode": "125003ATB",       // 일반명코드 — 주성분 파일 조인키
      "ingredientNameEn": "carvedilol",
      "dosageForm": "정제",
      "route": "내복",
      "classNo": "214",                    // 분류번호
      "representativeCode": "8806433003708",
      "packages": [
        { "kdCode": "8806433003708", "quantity": 0,   "dosageForm": null, "packageType": null },
        { "kdCode": "8806433003715", "quantity": 10,  "dosageForm": "정", "packageType": "PTP" },
        { "kdCode": "8806433003722", "quantity": 100, "dosageForm": "정", "packageType": "PTP" }
      ]
    }
  ]
}
```

### 주의

- `strengthLabel`은 업체마다 표기 기준이 다르다. 자누비아는 종근당 `128.9밀리그램`(염 기준), 한국엠에스디 `100밀리그램`이다. **화면의 함량 표기는 `itemName`을 기준으로 한다.**
- `quantity: 0` 행은 대표행이며 실제 포장이 아니다. 화면의 포장 목록에서 제외한다.
- `cancelDate`가 있는 품목은 기본 숨김, 필터로만 노출한다.

## 3. `data/public/billing.json`

```jsonc
{
  "schemaVersion": "0.2.0",
  "generatedOn": "2026-09-22",
  "source": {
    "noticeName": "약제 급여 목록 및 급여 상한금액표",
    "effectiveDate": "2026-09-01",
    "file": "약제급여목록및급여상한금액표_(2026.9.1.)_공개용(비인가자) 1부.xlsx",
    "url": "https://www.hira.or.kr/bbsDummy.do?pgmid=HIRAA030014050000"
  },
  "items": [
    {
      "itemKey": "199800085::(주)종근당",
      "ediCode": "643300370",              // 보험코드 9자리 = 급여목록표 '제품코드'
      "benefitStatus": "listed",           // listed | not-listed
      "maxPrice": 196,                     // 상한금액(원). not-listed 면 null
      "priceUnit": "1정",                  // 규격 + 단위 결합
      "noticeProductName": "딜라트렌정6.25mg(카르베딜롤)_(6.25mg/1정)",
      "mainIngredientCode": "125003ATB",
      "classNo": "214",
      "rxClass": "전문"
    }
  ]
}
```

### `benefitStatus` 해석 규칙

| 값 | 의미 | 화면 표기 |
|---|---|---|
| `listed` | 급여목록표에 존재 | `급여 · 상한 196원` |
| `not-listed` | 급여목록표에 없음 | `급여목록 미등재` |

**`not-listed`를 "비급여"로 단정하지 않는다.** 비급여·수출용·취소·미등재가 모두 이 상태로 나타난다. 화면 문구는 반드시 `급여목록 미등재 (비급여 여부는 별도 확인)`으로 쓴다.

> 예: 큐시미아 전 함량은 `not-listed`다. 비만치료제라 비급여일 가능성이 높지만 이 데이터만으로 단정할 수 없다.

### 조인 규칙

```text
zeroPad(약가마스터 '제품코드(개정후)', 9)  ==  급여목록표 '제품코드'
```

**선행 0 패딩이 필수다.** 약가마스터는 0으로 시작하는 보험코드를 8자리로 담고(`52300041`), 급여목록표는 9자리로 담는다(`052300041`). 패딩 없이 조인하면 프롤리아·이베니티·아토젯(한국오가논) 등 6품목이 **조용히 `not-listed`로 잘못 떨어진다.**

> 실측: 프롤리아프리필드시린지 `052300041` → 108,290원. 패딩 전에는 미등재로 보였다.

보험코드는 약가마스터에서 **대표행(quantity 0)에만 있는 경우가 있다.** 품목 단위로 먼저 채운 뒤 조인한다.

## 4. 브랜드 분리 규칙

브랜드명이 포함관계인 품목은 별도 브랜드로 분리한다. 문자열 포함만으로 묶으면 오분류된다.

| 상위 매칭 | 실제 분리 대상 | brandId |
|---|---|---|
| 리피로우 | `리피로우젯`(에제티미브 복합) | `lipilouzet` |
| 텔미누보 | `텔미누보플러스`(텔미사르탄/에스암로디핀/클로르탈리돈) | `telminuvo-plus` |
| 텔미누보 | `텔미누보에스` — 3품목 전부 2018-10-16 허가취소 | `null` (브랜드로 만들지 않음) |
| 텔미트렌 | `텔미트렌에스`(텔미사르탄/로수바스타틴) | `telmitren-s` |
| 텔미트렌 | `텔미트렌플러스`(텔미사르탄/히드로클로로티아지드) | `telmitren-plus` |

**업체명 검증을 반드시 거친다.** 브랜드 문자열만으로는 타사 동명 품목이 섞인다.

| 브랜드 | 요구 업체명 | 제외되는 품목 |
|---|---|---|
| 글리아티린 | 종근당 | `글리아티린연질캡슐`·`글리아티린주사액` ((주)대웅제약) |
| 사이폴 | 종근당 | `사이폴-엔연질캡슐50밀리그램` ((주)다산제약) |

전량 허가취소된 묶음은 브랜드로 만들지 않는다. 판매 중이 아닌 제품을 카탈로그에 올리면 현장에서 오해를 부른다.

## 5. 상태·최신성

| 필드 | 규칙 |
|---|---|
| `generatedOn` | 생성 실행일 |
| `source.effectiveDate` | 고시 시행일 — 화면 필수 표시 |
| stale 판정 | `effectiveDate` 기준 90일 초과 시 경고(검증 실패 아님) |

약가와 급여는 수시 개정된다. 기준일 없는 금액은 화면에 표시하지 않는다.

## 6. 검증 규칙 (validate-data.mjs v2)

기존의 숫자 고정 검사(`제품 40개`, `run 카운트 일치`)는 제거한다. 데이터가 늘수록 통과가 쉬워야 한다.

```text
형식   ediCode = 숫자 9자리 / kdCode = 숫자 13자리 / itemSeq = 숫자 9자리
참조   billing.itemKey → items.itemKey 존재
       items.brandId → products.id 존재
중복   itemKey 유일 / kdCode 유일
enum   benefitStatus ∈ {listed, not-listed}
값     maxPrice 는 listed 일 때 양의 정수, not-listed 일 때 null
최신성 source.effectiveDate 90일 초과 시 경고 출력
출처   모든 source URL https
```

기존 규칙 중 **`status === 'review'`인 품목이 ckd 링크를 가지면 실패**하는 규칙은 삭제한다. 검토 품목의 정보를 보강하면 검증이 깨지는 잘못된 규칙이다.

## 7. 화면이 지켜야 할 것

- 보험코드·표준코드는 **복사 가능**해야 한다. 현장에서 그대로 청구 화면에 옮긴다.
- 함량별 표가 제품 상세의 기본 노출 영역이다. 탭 안에 숨기지 않는다.
- 코드(보험코드·표준코드) 역검색을 지원한다.
- 금액 옆에 고시 시행일을 붙인다.
- 공동판매 품목은 **허가권자와 판매사를 분리 표시**한다. 프롤리아처럼 종근당 명의 코드가 없는 품목도 있다.
- 고정 문구: `코드와 금액은 참고용입니다. 실제 청구는 심평원 고시 원문과 의료진 판단을 따릅니다.`
