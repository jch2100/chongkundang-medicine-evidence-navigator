# 공공데이터포털 인증키 발급 가이드

대상: 식약처 의약품 허가정보 · DUR 품목정보 · DUR 성분정보 (3종)
소요: 최초 1회 약 10분 + 키 반영 대기 최대 1시간
비용: 무료

> 심평원 약가마스터·상병마스터는 **파일데이터**라 인증키가 필요 없습니다. 이 문서는 OpenAPI 3종에만 해당합니다.

---

## 핵심 먼저

- 인증키는 **계정당 1개**입니다. 3개 API를 각각 신청하지만 키는 하나를 공용으로 씁니다.
- 개발계정은 **자동승인**이고 트래픽은 API당 10,000건/일입니다. 우리 용도(품목 수백 건)에는 충분합니다.
- 신청 직후 바로 호출하면 실패할 수 있습니다. **키 반영에 최대 1시간**이 걸립니다.

---

## 1단계 — 회원가입 / 로그인

1. https://www.data.go.kr 접속
2. 우측 상단 `로그인`
3. 계정이 없으면 `회원가입` → 일반회원. 네이버·카카오 간편가입도 됩니다.
4. 이메일 인증 완료

---

## 2단계 — 3개 API 활용신청

아래 3개 링크를 각각 열어 **같은 절차**를 반복합니다.

| # | 데이터명 | 링크 |
|---|---|---|
| 1 | 식품의약품안전처_의약품 제품 허가정보 | https://www.data.go.kr/data/15095677/openapi.do |
| 2 | 식품의약품안전처_의약품안전사용서비스(DUR)품목정보 | https://www.data.go.kr/data/15059486/openapi.do |
| 3 | 식품의약품안전처_의약품안전사용서비스(DUR)성분정보 | https://www.data.go.kr/data/15056780/openapi.do |

각 페이지에서:

1. 우측 상단 **`활용신청`** 버튼 클릭
2. **활용목적 선택** → `웹 사이트 개발` 선택
3. **활용목적 상세** 입력란에 아래를 붙여넣기:

   ```
   의약품 허가정보·DUR 정보를 참조하는 비영리 공개 참고 웹페이지 제작
   ```

   (첨부파일은 필요 없습니다)
4. **시스템 유형** → `일반` 선택 (서버 IP 등록 불필요)
5. **상세기능 선택** → 목록이 전부 체크되어 있는지 확인. 체크가 없으면 전체 선택
6. 하단 **라이선스 표시 동의** 체크
7. **`활용신청`** 클릭

→ `승인` 상태로 바로 넘어갑니다. 심의를 기다릴 필요 없습니다.

---

## 3단계 — 인증키 확인

1. 우측 상단 **`마이페이지`**
2. 좌측 메뉴 **`데이터활용` → `Open API` → `활용신청 현황`**
3. 신청한 API 중 아무거나 클릭 → 상세 화면
4. 화면 중간의 **`일반 인증키(Decoding)`** 값을 복사

   - `일반 인증키(Encoding)` / `(Decoding)` 두 가지가 보입니다.
   - **둘 중 아무거나 넣어도 됩니다.** 확인 스크립트가 형태를 판별해 자동 변환합니다.

---

## 4단계 — 키를 로컬 파일에 저장

### 먼저 확인: API 3개의 키가 정말 다른 값인가

data.go.kr의 일반 인증키는 **API별이 아니라 계정별**입니다. API를 3개 신청하면 신청 건이 3개로 보이고 각 상세 화면마다 인증키가 표시되지만, **표시되는 값은 같은 키 하나**인 경우가 대부분입니다.

확인법: 세 화면의 `일반 인증키(Decoding)` 값에서 **앞 10글자와 뒤 10글자만** 비교하세요. 같으면 키는 1개입니다.

### 방식 A — 세 값이 같을 때 (일반적)

프로젝트 루트에 **`.env.local`** 파일을 만들고 한 줄만 넣습니다.

```
DATA_GO_KR_KEY=여기에_Decoding_키_붙여넣기
```

### 방식 B — 세 값이 다를 때

API별로 나눠 넣습니다. 어느 키가 어느 API 것인지 헷갈려도 됩니다. 확인 스크립트가 다른 키로 자동 재시도해서 맞는 조합을 찾아 알려줍니다.

```
DATA_GO_KR_KEY_PERMISSION=의약품_제품_허가정보_키
DATA_GO_KR_KEY_DUR_PRDLST=DUR_품목정보_키
DATA_GO_KR_KEY_DUR_IRDNT=DUR_성분정보_키
```

### 공통 주의사항

- 따옴표 없이, 등호 앞뒤 공백 없이
- 메모장으로 저장할 때 인코딩은 **UTF-8**
- 저장소에는 들어가지 않습니다 (`.gitignore`에 `.env.*` 이미 포함)
- 이 키는 채팅·이슈·커밋 어디에도 붙여넣지 마세요

## 5단계 — 동작 확인

프로젝트 루트에서:

```bash
node scripts/check-api-key.mjs
```

정상이면:

```
.env.local 에서 키 3개 확인 (서로 다른 값 1개)
→ 세 항목의 값이 모두 같습니다. DATA_GO_KR_KEY 한 줄로 줄여도 됩니다.

[OK]   의약품 제품 허가정보 · totalCount=XXXXX · 사용한 키: DATA_GO_KR_KEY_PERMISSION
[OK]   DUR 품목정보(병용금기) · totalCount=XXXXX · 사용한 키: DATA_GO_KR_KEY_DUR_PRDLST

인증키 정상입니다.
```

첫 줄이 키 개수를 알려주므로, 방식 A/B 중 무엇을 골라야 할지 고민하지 말고 일단 3개를 넣고 돌려도 됩니다.

> DUR 성분정보는 확인 대상에서 빠져 있습니다. 요청주소를 아직 확정하지 못했고, 키는 위 두 건으로 충분히 검증되기 때문입니다. 실제 수집기(S3)를 만들 때 포털 화면의 요청주소를 확인해 추가합니다.

## 오류가 날 때

| 메시지 | 원인 | 조치 |
|---|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 키 반영 전 (가장 흔함) | 1시간 뒤 재시도. 마이페이지에서 신청 상태가 `승인`인지도 확인 |
| `.env.local 없음` | 4단계 누락 | 파일 위치가 프로젝트 루트인지 확인 |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | 일일 10,000건 초과 | 다음날 재시도 |
| `NO_OPENAPI_SERVICE_ERROR` | 엔드포인트 버전이 존재하지 않음 | 버전 접미사를 올려가며 확인하거나 포털의 요청주소 복사 |
| 한 API만 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | **구버전 엔드포인트 호출** | 아래 참고 |

### 실제 사례 — 승인됐는데 한 API만 거부될 때

2026-09-22에 겪은 경우입니다. 마이페이지 상태는 `승인`이고 DUR은 정상인데 허가정보만 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 났습니다.

원인은 **엔드포인트 버전**이었습니다. 식약처 API는 개정될 때마다 접미사가 올라가고(`...Service07` → `...Service08`), **구버전에는 신규 키가 등록되지 않습니다.** 기존 이용자만 구버전을 계속 쓸 수 있습니다.

판별법: `NO_OPENAPI_SERVICE_ERROR`는 그 버전이 아예 없다는 뜻이고, `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`는 **버전은 있는데 내 키가 그 버전에 등록되지 않았다**는 뜻입니다. 후자가 뜨면 버전을 한 단계 올려 보세요.

현재 확인된 유효 버전:

```
의약품 제품 허가정보  DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnInq08
DUR 품목정보         DURPrdlstInfoService03/getUsjntTabooInfoList03
```
