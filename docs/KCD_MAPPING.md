# 상병코드(KCD) 매핑 규칙 — S2 설계

상태: 방법 확정 · 매핑 데이터 생성 전
기준 자료: 건강보험심사평가원 상병마스터 20250930 (`data/source/`)

---

## 1. 이 레이어가 하는 일과 하지 않는 일

| 한다 | 하지 않는다 |
|---|---|
| 허가 적응증에 대응하는 KCD 코드 **후보**를 보여준다 | 청구할 상병코드를 지정한다 |
| 코드가 청구 가능한 형태인지 검증한다 | 급여 인정 여부를 판정한다 |
| 급여 기준 고시 원문으로 연결한다 | 고시 내용을 요약해 단정한다 |

**허가 적응증 · 급여 인정 상병 · 실제 청구 상병은 서로 다르다.** 이 문서는 첫 번째에서 두 번째로 가는 다리만 놓고, 세 번째는 의료진의 판단 영역으로 남긴다.

---

## 2. 상병마스터 구조 (실측)

```text
전체 행    47,798
고유 코드  21,299     ← 한 코드에 동의어·색인어 행이 여러 개 붙는다
자릿수     3자리 3,718 / 4자리 21,053 / 5자리 21,628 / 6자리 1,399
```

컬럼: `상병기호` `한글명` `영문명` `완전코드구분` `주상병사용구분` `법정감염병구분` `성별구분` `상한연령` `하한연령` `양한방구분`

### 동의어 행 처리

`E11`(2형 당뇨병)은 6행이다. `비케톤성 당뇨병`, `성인발병당뇨병` 등 색인어가 각각 한 행을 차지한다.
→ **코드 단위로 중복 제거하고, 대표 한글명은 첫 행을 쓴다.** 동의어는 검색용으로만 보관한다.

## 3. 가장 중요한 규칙 — 완전코드만 제시한다

`완전코드구분` 값의 의미는 다음과 같다.

| 값 | 의미 | 청구 |
|---|---|---|
| `N` | **불완전코드** — 하위 세분류가 있어 단독 사용 불가 | 불가 |
| (빈값) | **완전코드** | 가능 |

### 실측 예시

```text
I10   불완전   본태성(원발성) 고혈압
 └ I101  완전   악성 고혈압
 └ I109  완전   기타 및 상세불명의 원발성 고혈압

M81   불완전   병적 골절이 없는 골다공증
 └ M810  불완전  폐경후골다공증
    └ M8100 완전  폐경후골다공증, 여러 부위
    └ M8101 완전  폐경후골다공증, 어깨부분      (부위별 99개)

H401  불완전   원발성 개방우각녹내장
 └ H4010 완전  저안압녹내장
 └ H4019 완전  상세불명의 원발성 개방우각녹내장

E780  불완전   순수 고콜레스테롤혈증
 └ E7800 완전  가족성 고콜레스테롤혈증
 └ E7808 완전  기타 및 상세불명의 순수고콜레스테롤혈증
```

**딜라트렌의 상병코드를 `I10`으로 표시하면 틀린 안내가 된다.** 실제 청구 코드는 `I109` 같은 완전코드다. 골다공증은 부위까지 들어가 `M8100` 수준이 된다.

화면에서는 불완전코드를 **분류 헤더**로만 쓰고, 복사 가능한 코드로 제시하지 않는다.

## 4. 매핑 절차

```text
1. 허가 적응증 원문 확보        의약품안전나라 품목 상세 (itemSeq)
2. KCD 블록 후보 선정           사람이 판단. 자동 매핑 금지
3. 완전코드로 전개              상병마스터에서 하위 완전코드 추출
4. 코드 유효성 검증             상병마스터 존재 + 완전코드 여부 + 성별·연령 제한 확인
5. 급여 조건 분리 기록          고시에 상병 제한이 있으면 noticeRef 와 함께 별도 필드
6. 검토자·검토일 기록           mappedBy / mappedOn
```

2단계를 자동화하지 않는 이유: 적응증 문구와 KCD 분류는 1:1이 아니다. "고혈압"은 `I10~I15`에 걸치고, 어느 범위가 해당 품목의 적응증인지는 허가사항을 읽어야 안다.

## 5. 데이터 형식 (`data/public/indications.json`)

```jsonc
{
  "schemaVersion": "0.2.0",
  "source": { "diseaseMaster": "건강보험심사평가원_상병마스터_20250930.csv" },
  "items": [
    {
      "brandId": "dilatrend",
      "itemKey": "199800085::(주)종근당",
      "labelIndicationText": "본태성 고혈압",          // 허가사항 원문 문구
      "labelSourceUrl": "https://nedrug.mfds.go.kr/...",
      "kcdCandidates": [
        { "code": "I109", "nameKo": "기타 및 상세불명의 원발성 고혈압", "complete": true },
        { "code": "I101", "nameKo": "악성 고혈압", "complete": true }
      ],
      "kcdBlockLabel": "I10 본태성(원발성) 고혈압",     // 화면의 분류 헤더 (복사 불가)
      "reimbursementScope": null,                     // 고시상 상병 제한. 확인 전에는 null
      "noticeRef": null,
      "mappedBy": null,
      "mappedOn": null
    }
  ]
}
```

`reimbursementScope`가 `null`인 동안에는 화면에 급여 관련 문구를 **표시하지 않는다.** 빈 값을 "제한 없음"으로 읽히게 두지 않는다.

## 6. 검증 규칙 (validator 추가분)

```text
존재    kcdCandidates[].code 가 상병마스터에 존재
완전성  kcdCandidates[].code 는 모두 완전코드 (완전코드구분이 빈값)
일치    nameKo 가 상병마스터의 대표 한글명과 일치
참조    itemKey → items.json 존재
필수    labelIndicationText 와 labelSourceUrl 이 함께 존재
검토    mappedBy/mappedOn 없으면 공개 상태로 올리지 않음
```

---

## 7. 화면 표기 규칙

- 코드 옆에 항상 한글명을 붙인다. 코드만 보여주면 오입력 위험이 커진다.
- 성별·연령 제한이 있는 코드는 배지로 표시한다 (상병마스터의 `성별구분`, `상한연령`, `하한연령`).
- 고정 문구:

> 상병코드는 허가 적응증에 대응하는 **참고 매핑**입니다. 실제 청구 상병은 환자 상태와 심평원 고시 기준에 따라 의료진이 판단합니다.

## 8. 15개 브랜드의 탐색 범위 (후보 블록, 확정 아님)

적응증 원문 확보 전 단계의 **탐색 출발점**이다. 이 표를 그대로 데이터로 쓰지 않는다.

| 브랜드 | 치료 영역 | 탐색 블록 |
|---|---|---|
| 딜라트렌 | 고혈압·심부전 | I10~I15, I50 |
| 텔미누보 / 텔미트렌 | 고혈압 | I10~I15 |
| 리피로우 / 아토젯 | 이상지질혈증 | E78 |
| 자누비아 | 2형 당뇨병 | E11 |
| 프롤리아 / 이베니티 | 골다공증 | M80, M81 |
| 타크로벨 / 마이렙트 / 사이폴 | 이식 면역억제 | Z94, T86 |
| 글리아티린 | 뇌대사·인지 | F00~F03, G30 |
| 펙수클루 | 위식도역류 | K21 |
| 고덱스 | 간질환 | K70~K77 |
| 큐시미아 | 비만 | E66 |

이식(`Z94`/`T86`)과 치매(`F00`/`G30`) 영역은 급여 기준이 까다로운 대표 영역이므로, 급여 고시 확인을 먼저 하고 코드 후보를 좁힌다.
